validEpochMs()

Returns the number unchanged if it is a finite millisecond value, otherwise throws.

function validEpochMs(epochMs: number): number

Description

An invalid Date has getTime() === NaN. If that NaN reached the zone maths it would quietly produce NaN everywhere and print "NaN/NaN/NaN" on screen. This guard stops it at the door with a clear RangeError("Invalid instant").

Why it exists

Stops an invalid Date (NaN) before it spreads into "NaN/NaN/NaN" on screen.

  • An invalid Date does not throw; it silently holds NaN, and every calculation after that is also NaN.
  • Failing fast with a named error makes the bad value easy to trace back to its source.

Without it: Bad input would show as "NaN" text or be sent to the API as "Invalid Date".

Step by step

  1. If Number.isFinite(epochMs) is false, throw.
  2. Otherwise return the same number.

Examples

Source

function validEpochMs(epochMs: number): number {
  if (!Number.isFinite(epochMs)) {
    throw new RangeError('Invalid instant');
  }
  return epochMs;
}
