# 8.0 date picker spike and 0.5 zone library

Date: 2026-10-08. Repos: Frontend (Angular 19.2, Material 19.2), HandoverApp and InspectionsApp (Angular 16.2, Material 16.2).

## Outcome

Angular Material's date picker can run on the team's wall clock. No own calendar popup is needed. `TeamZoneDateAdapter` is a custom `DateAdapter<Date>` and the same source file is used on Angular 19 and Angular 16.

## How the adapter works

| Question | Answer |
|---|---|
| What is a "date" for Material? | A `Date` at UTC midnight whose **UTC fields** hold the team's calendar day. Year, month, day and weekday are read with `getUTC*`, so the device zone never touches the calendar grid. |
| "Today" highlight | `today()` converts the current instant to the team zone and returns that day. The clock is injectable (`TIME_KIT_NOW`) so tests can freeze it. |
| Typed text | `parse` and `format` use the team date format (`dd/MM/yyyy`, `MM/dd/yyyy`, `yyyy-MM-dd`, `dd.MM.yyyy`). Unreadable text returns an invalid `Date`, so Material sets `matDatepickerParse` and the control sets `dateTimeInvalid`. |
| Value that leaves the control | The control never returns the pseudo date. `date` mode returns the team's midnight as UTC (`calendarDateToWire`). `dateTime` and `time` modes combine the day with the typed time through `teamWallClockToUtc`. |
| Time part | Not part of the picker. A text input parsed with the team time format (`HH:mm` or `h:mm a`), so the device's 12 or 24 hour setting is ignored. |
| Scope | The adapter and `MAT_DATE_FORMATS` are provided on the `<app-date-time-field>` component, so they override the global `provideNativeDateAdapter()` / `UKDateAdapter` only inside the control. Nothing else in the apps changes. |
| Week start | Monday (as the UK adapter did). |

## Pass criterion of the plan, and the evidence

"A Toronto device on a London team, near London midnight, highlights the London day and returns the right UTC value."

Spec `DateTimeFieldComponent date mode highlights the London day and returns the London midnight for a Toronto device just after London midnight`:

- Frozen now: `2026-07-15T23:30:00Z` (London 00:30 on 16 July, Toronto 19:30 on 15 July).
- The open calendar marks **16** as today (`.mat-calendar-body-today`).
- Clicking **17** gives the form value `2026-07-16T23:00:00.000Z` (London midnight of 17 July) and the input shows `17/07/2026`.
- The spec runs in a real headless Chrome with the process zone set to `America/Toronto`, `Pacific/Auckland` and `Europe/London` (`npm run test:tz`), on Angular 19 (Frontend) and Angular 16 (HandoverApp, InspectionsApp). All green.

Pure-logic vectors for the same behaviour (both clock-change days, seven zones) are in `time-core.spec.ts`, `date-time-input.spec.ts` and `team-calendar.spec.ts`; they use the same expected values as the backend `TeamDateTimeProviderTests` (spring gap moves forward, autumn repeated hour takes the first occurrence).

## Known limits

- Material's own labels ("Open calendar", "Choose month and year") stay English: `MatDatepickerIntl` is not translated yet. A Phase 9 item if wanted.
- `min`, `max` and a date filter are not exposed on `<app-date-time-field>` yet. Add them when the first screen needs them; the adapter already supports `compareDate`.
- HandoverApp themes only the legacy Material components (`all-legacy-component-themes`), so the MDC form field and input themes were added to its `styles.scss`. Visual check on a device is still advised.

## 0.5 Zone library

Decision: **`Intl.DateTimeFormat` with `timeZone`, no new dependency.** `date-fns-tz` is not used.

- `time-core.ts` derives every offset from `Intl.DateTimeFormat(...).formatToParts` for the exact instant, so offsets are always worked out per date from the IANA id (rule Z4).
- Gap and repeated-hour rules are implemented in the same way as the backend (`TeamDateTimeProvider.ToUtc`): a time inside a gap moves forward in 30 minute steps to the first valid time, a repeated time takes the first occurrence (larger offset).
- Formatters are cached per zone.
- The apps stay on date-fns 2; the kit does not import it.
