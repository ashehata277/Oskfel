The answer

Simplest to ship: team-zone-headers. Most complete: UTC. Simplest day logic: team-local, while every team is London.

  • Headers and UTC store the same thing. Choosing headers now keeps the UTC route open: the UTC plan's extra work (Attendance pay-rule fixes, night-shift pairing, WireDate on every entry point, TZ removed from containers) can follow later with no migration.
  • Team-local is the only one-way door. It rewrites 118 collections and 12 event stores, changes what Z means to every outside reader, and needs its Phase 8 before any non-London team.
  • Headers gives up the UTC plan's pay-rule fixes and its full clean-up. It keeps today's Attendance rules exactly, so London wages only move on the signed-off day-boundary list.
  • Recommendation (author's opinion): the team-zone-headers plan now, and the UTC plan's remaining items later as separate work, unless the Attendance pay-rule fixes must ship in the same release (then the UTC plan).

Which plan works more easily with external services

UTC and headers, equally. Both keep Z as real UTC, the standard every outside API, library and tool expects. In team-local Z holds the wall clock, so almost every boundary with the outside needs a conversion.

How to choose

Answer from the top; the first answer that points to a plan decides.

Part A · Can team-local work for us at all?
Q1Must a non-London team start before team-local's Phase 8 could be built?yes → Part C
Q2Is there an outside consumer that one conversion layer cannot serve?yes → Part C
Q3Can every service stop for the long migration night?no → Part C
Part B · Is team-local worth it?
Q4Will every team stay London for years, and are per-team reports straight on MongoDB a main reporting path?yes → Team-local
Part C · UTC storage: which plan?
Q5Must the Attendance pay-rule fixes (7 pay-affecting changes, night-shift pairing) ship in the same release?yes → UTC
Q6Must the full clean-up land now: WireDate on every entry point, Kind=Utc, no TZ in containers?yes → UTC
Otherwise → team-zone-headers. The UTC plan's extras can follow later on the same storage, with no migration.

The smallest build no longer points to team-local on its own: the headers plan is about the same size and needs no migration night.
