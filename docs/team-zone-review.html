Team Zone Review

What the team-zone-headers work changed about time, why, and how it was checked. ProjectService was the pilot; the other 12 services now follow the same design.

The rule

Store and send every instant as UTC. Apply the team's zone only where a person sees a day, a month or a printed date.

Each request carries the team's settings in headers:

HeaderMeaning
Intowork.TeamTimeZoneIANA zone, for example Europe/London. Required; missing or invalid gives 400.
Intowork.TeamDateFormatDate format, default dd/MM/yyyy.
Intowork.TeamTimeFormatTime format, default HH:mm.
Intowork.TeamNameThe team. Background work takes it from the message instead.

One clock

All code reads time through IDateTimeProvider from the shared Intowork.Common.Time package (1.0.0-alpha.11368). It has one implementation, created once per scope. Each service's old Time/ folder was deleted.

Where code runsWhere the zone comes from
Only needs "now"No zone needed: clock.UtcNow
API requestThe request headers
Event handlerawait clock.UseTeamAsync(@event.TeamName, token) before any write
Hosted service or loop over teamsA new scope per team, then UseTeamAsync
  • Call UseTeamAsync once, and only if the code reads the zone. A second call throws.
  • A team with no valid zone throws TeamTimeUnavailableException. Don't catch it; the message retries. There is no fallback zone.
  • Each event runs in its own DI scope (RunEachEventInItsOwnScope()), so two messages never share a clock.

The other services

All 12 other services (ActiveWork, Attendance, Customer, Forecasting, Gaffer, Handover, Inspections, Materials, Notification, Permissions, Resources, SafetySuite) were moved onto the package on 14 October. Each feature branch is pushed and merged into its -develop branch together with origin/develop.

  • Attendance: the pay window, weekends and pay weeks use the team zone. See the Attendance review.
  • Handover: develop replaced the PDF reports with a new certificate generator. On -develop it now uses the package's zones and formats.
  • ActiveWork, Inspections: report templates with an explicit format now print AM/PM correctly.

Open questions

  1. Older clients get 400. Do we ship the apps first, or have the Gateway fill in the header for a while?
  2. Repeated hour. Is "take the earlier instant" right for clock-outs entered during the repeated hour?
  3. Scope per message. ScopedEventHandler is copied into 8 services. Should it move into Common.Messaging?
  4. Moving a team. If a team ever changes zone, is a data migration the agreed path?
  5. Package tests. Intowork.Common.Time has no test project of its own yet.
