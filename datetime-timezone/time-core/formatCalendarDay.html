formatCalendarDay()

{ year, month, day } → "yyyy-MM-dd".

function formatCalendarDay(parts: Pick<WallClock, 'year' | 'month' | 'day'>): CalendarDay

Description

A CalendarDay is a date with no time and no zone, such as a birthday or a due date. It is always stored as the string yyyy-MM-dd. This function builds that string from its three parts, padding each one.

Why it exists

Calendar days are stored as "yyyy-MM-dd" strings, and something has to build them.

  • Date-only values (due dates, birthdays) must not carry a time or zone, otherwise they move across midnight when converted. A plain string avoids that completely.
  • Building the string in one place guarantees the zero padding is always correct.

Without it: Date-only fields stored as Date objects, which shift by a day for users east or west of UTC.

Step by step

  1. Pad the year to 4 digits, the month and day to 2, and join them with dashes.

Examples

These outputs were produced by running the real function.

formatCalendarDay({ year: 2026, month: 3, day: 5 })
"2026-03-05"
formatCalendarDay({ year: 99, month: 1, day: 1 })
"0099-01-01"

Good to know

  • It does not check the day is real; run parseCalendarDay on the result when the parts are not already known to be valid.

Source

export function formatCalendarDay(parts: Pick<WallClock, 'year' | 'month' | 'day'>): CalendarDay {
  return `${pad(parts.year, 4)}-${pad(parts.month, 2)}-${pad(parts.day, 2)}`;
}
