Attendance Team Zone Review

In Attendance, time zones decide pay. Clock-in rounding, the 08:00–16:00 pay window, weekend rates and pay weeks all depend on which day and hour a clock reading falls in. Before this work, all of it used London time for every team.

How the clock works now

  • Clock readings are stored as UTC. The team's zone decides the day, weekday and hour.
  • Code reads time only through IDateTimeProvider from Intowork.Common.Time. The in-repo Time/ folder was deleted.
  • Requests get the zone from headers. Background handlers call UseTeamAsync(teamName) before writing anything, so a team with no zone fails cleanly and the message retries.
  • Each event runs in its own scope. The reminder service and ShadowCompare open one scope per team.
  • The clock is passed down the whole wage pipeline: recalculate → travel and breaks → wages → bonus → deductions.

What was wrong and how it was fixed

ProblemFix
London was hard-coded in six helpersDeleted; each method takes the team clock

The 08:00 pay-window check compared against UTC hours, so 08:59 BST was paid as on time08:00 and 16:00 are worked out in the team's zone

"Same day" used .Date on UTC valuesThe attendance record holds a clock and compares team days
Pay weeks and periods ended at UTC midnightThey run from team midnight to team midnight; a DST week is 167 or 169 hours
Reminders ran on one London schedule for every teamOne Hangfire job pair per team zone
Handlers saved work before they knew the zoneThe zone is resolved first; failures retry from a clean state
Overlap messages showed London HH:mmTeam zone and the team's time format, for example 9:30 AM

Proving pay didn't change: characterisation tests record today's London results, and the refactored code has to match them. Intowork.Attendance.ShadowCompare recalculates past pay weeks from a database copy and reports any difference.

Merging into -develop

Most conflicts were only line endings. Develop also added new code that still assumed London, and it was fixed in the merge commit:

  • Incremental attendance rebuild: kept as written, but it uses the injected clock.
  • Bulk supervisor clock-in/out: uses the team clock for records, time rounding and overlap messages. The London lookup was deleted.
  • Lock expiry and controller logs: read the injected clock instead of DateTime.Now.
