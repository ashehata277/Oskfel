Inbound: API → model

P01

Response models: interface + raw JSON → class with teamDate() per field

Done
6096094c0 · 0f3afdf93≈280 interfaces became classes · 292 constructors in 65 files · 336 teamDate() calls

Why the old code was wrong. Fields typed as Date were really UTC ISO strings at runtime. Each screen then parsed them its own way, usually in the device zone.

Before
export interface StaffAbsence {
  startDate: Date;
  endDate: Date;
}

this.http.get<StaffAbsence[]>(url);
After
export class StaffAbsence {
  startDate: Date;
  endDate: Date;

  constructor(data: any = {}) {
    Object.assign(this, data);
    this.startDate = teamDate(data.startDate);
    this.endDate = teamDate(data.endDate);
  }
}

this.http.get<StaffAbsence[]>(url).pipe(map((items) => items.map((item) => new StaffAbsence(item))));

Where: Every *.ts model under activework/, attendance/, materials/, resources/, jobs/, quotations/, safety-suite/, …

Gotchas

  • Object.assign copies every raw field first. A date field without its own teamDate() line silently stays a string.
  • Nested models must be rebuilt explicitly: data.items?.map((item) => new Item(item)).
  • teamDate() only converts strings. Arrays of instants need .map(teamDate).

Done
38918292aBankHoliday, StaffAbsence models + consumers

Why the old code was wrong. A day stored as 2026-12-25T00:00:00Z that goes through teamDate() lands on 24 Dec for any team west of UTC. A day has no zone, so it must never be converted.

Before

  day: CalendarDay | null;
  constructor(data: any = {}) {
    Object.assign(this, data);

Common points across all patterns

Moment vs day

Ask first whether the value is a moment (clock-in, created at) or a day (bank holiday, absence, assignment date). Moments go through teamDate/asTeamDate/isTeamPast; days go through calendarDay/teamDayText/isTeamDayBeforeToday. Most remaining bugs (O3, O9, O13) come from mixing the two.

Convert once, at the edge

Inbound conversion belongs in the model constructor (P01). In components, asTeamDate is a safety net, not the main path. If a component needs it for a value from an API, the model is missing a teamDate line.

Never mix parsers in one expression

new Date(a) > asTeamDate(b) compares a real instant with a shifted one. Both sides must be team Dates (O5, O6).

Already-UTC values

Values built with Date.UTC(...) or buildUtcRange are real instants. Don't pass them through utcDate or teamIso again, and say so on the request type (P18).

Object.assign copies everything

Every date field in a constructor needs its own line. Nested arrays need .map((item) => new Item(item)).

Wire strings must end in Z

Offset-less strings trigger the teamDate dev warning and are read as device-local by asTeamDate (O2). Treat each warning as a backend bug.

Two picker adapters

Raw matDatepicker uses local-midnight Dates (TeamFormatDateAdapter); <app-date-time-field> uses UTC-field Dates internally but emits team Dates. Only the field's emitted value is a team Date.

Sentinels on shifted Dates

Tests like getFullYear() === 1970 fail for teams west of UTC. Check sentinels on the raw value (O4).

Specs

Always pin the team zone, the device zone and now with kitTestProviders, using a device zone that differs from the team zone, and reset TeamDateBoundary.current.

PR review checklist for date-time changes

  • No new isToday, isPast, isFuture, parseJSON, parseISO or new Date() outside shared/time; npm run check:time passes with a committed baseline.
  • Every new date field in a response model has a teamDate() line (moment) or a calendarDay() line (day).
  • Every date in a request body goes through utcDate() / xxxToUtc(), unless the request type says it is already UTC.
  • Day logic compares yyyy-MM-dd strings, never isSameDay(new Date(...)).
  • Displayed dates use <app-date-time> or TeamDateFormatter with a named format.
  • New inputs use <app-date-time-field>; min/max get team Dates or wire strings.
  • Specs touching dates use kitTestProviders with a device zone different from the team zone.
  • No dev-console teamDate warnings on the screens you changed.
